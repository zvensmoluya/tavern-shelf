# 角色卡关联展示

每份不同原件都是独立收藏卡：保留自己的封面、收藏时间、收藏夹、备注及下载/传输入口。关联只是帮助浏览的展示关系，不存在主卡、默认版本或跨卡封面选择。

## 自动关联

- 整个文件 SHA-256 相同：已收藏，不因改文件名新增卡片。
- 完整角色卡 JSON 的确定性指纹相同：关联，标记数据相同；PNG 与 JSON 使用同一规则。只换封面也各自保留。
- 数据不同，但名称和作者均非空且去除首尾空白后一致：关联，展示可确定的字段变化。
- 作者为空且数据变化、名称不完整或存在多个候选关联组：独立收藏，不根据大致相似程度猜测。

数据指纹忽略 JSON 排版和对象键顺序，保留文本、数组顺序、数字精度、未知扩展和 envelope 字段。损坏、重复对象键或过深嵌套的数据不生成指纹，仍保留可识别的角色卡原件。封面像素指纹仅用于描述文件变化，不用于判断卡片归属。

## 展示与操作

书架先按用户选择排序，再把关联卡放在该组第一张匹配卡的旁边，不隐藏或合并任何卡。每张卡显示自己的封面、名称、文件名及关联卡数量。筛选与搜索只检查该卡；关联关系不使不符合条件的卡混入结果。收藏、收藏夹数量和收录时间都按单张卡处理。

详情保持当前卡的独立封面与下载入口，用横向缩略卡片展示关联卡，标明文件名、收藏时间及数据关系。点击后切换整张卡的详情和下载对象。更多菜单包含建立关联、移出关联，移出后可以撤销；这些操作只更新关联元数据。

## 持久化

`characters.id` / `sourceHash` 继续对应原件。`contentHash` 是可重建的数据指纹，`groupId` 是持久化的展示关联，`groupReason` 记录依据。旧库从 Managed Source 安全重建；原件、收藏信息与时间不变。备份及回收站保存关联关系，重复备份恢复不会覆盖现有卡的手动关联。

`PUT /api/characters/{id}/association` 接受 `action: "join"` 或 `"split"`。`join` 的 `target` 是另一张现存卡的 ID，只将当前卡加入目标的展示关联；不会移动其他关联卡。下载和传输始终使用各自的原件 ID。

## 验证范围

Go 测试覆盖数据与封面指纹、归属判断、失败路径、移出关联、手动关联、独立收藏计数、备份/回收站及旧库重建。UI 验证覆盖独立卡列表、相关卡相邻、独立封面和下载、关联切换、收藏/筛选独立性、更多菜单、失败重试、移出/撤销、空库与窄窗口。

Windows 无控制台、单实例、关闭驻留、托盘及自启等系统级行为未在本次展示调整中重新验证。
